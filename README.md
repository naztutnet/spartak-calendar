# Календарь матчей ФК «Спартак-Москва»

Этот репозиторий используется для публикации календаря матчей мужской футбольной команды **«Спартак-Москва»** в формате iCalendar (`.ics`).

## Подписка на календарь

После добавления файла календаря его можно подключить на iPhone, Mac, в Google Calendar и других приложениях.

Ссылка для подписки через `webcal`:

```text
webcal://raw.githubusercontent.com/naztutnet/spartak-calendar/main/spartak-moscow.ics
```

Обычная HTTPS-ссылка:

```text
https://raw.githubusercontent.com/naztutnet/spartak-calendar/main/spartak-moscow.ics
```

## Как подключить на iPhone

1. Откройте **Настройки**.
2. Перейдите в **Приложения → Календарь → Учётные записи календаря**.
3. Нажмите **Добавить учётную запись → Другое**.
4. Выберите **Добавить подписной календарь**.
5. Вставьте ссылку `webcal://` и сохраните подписку.

После обновления файла `.ics` изменения будут автоматически появляться у подписчиков календаря.

## Содержимое репозитория

- `README.md` — описание проекта и инструкция по подключению.
- `spartak-moscow.ics` — календарь матчей «Спартака».

## Важно

Расписание матчей может меняться из-за переносов, решений лиги, телевизионных трансляций и участия клуба в турнирах. Перед поездкой на матч рекомендуется проверять дату и время на официальных ресурсах клуба и турнира.

## Автоматическое обновление после матча

GitHub Actions проверяет завершённые матчи каждый час. После подтверждения результата:

- счёт добавляется в название и описание существующего события;
- добавляется ссылка на официальный обзор Матч ТВ, если он опубликован;
- добавляется ссылка на полную легальную запись Матч ТВ, если она доступна.

UID события сохраняется, поэтому подписной календарь обновляет существующий матч без дубля. Появление изменений на iPhone также зависит от интервала обновления подписных календарей Apple.

Файлы автоматизации:

- `update_results.py` — обновление расписания и результатов с сохранением уже добавленных видеоссылок;
- `.github/workflows/update-results.yml` — ежечасный запуск и публикация обновлённого ICS.

## Устойчивость источников

Основной источник — календарь Чемпионата. Каждый адрес проверяется целиком:
успешный HTTP-ответ ещё не означает, что пришли матчи. Страницы SberID,
CAPTCHA, неожиданный тип ответа и неполный календарь отклоняются. После
ошибки содержимого проверяется следующий адрес, затем независимый резерв:
https://www.sports.ru/football/club/spartak/calendar/.

Резерв работает только с уже известными матчами сезона 2026/27: 30 туров
РПЛ и 6 туров группового этапа Кубка. Номер тура берётся из единственного
совпадающего существующего X-SOURCE-ID (турнир, хозяева, гости), не из
порядка строк. Новые турниры, плей-офф и новый сезон требуют отдельного
сопоставления и тестов; неизвестные матчи не добавляются наугад.

Если в резерве нет времени, не указаны пенальти или есть расхождение с
зафиксированной официальной датой, соответствующий матч сохраняется без
изменений. Такая строка не считается новым наблюдением. Резерв не является
полноценной проверкой точного времени всех 36 матчей: число распознанных и
число отложенных строк выводятся отдельно. При работе резерва Actions
показывает предупреждение. Если ни один источник не даёт полный поддерживаемый
список, запуск завершается ошибкой, календарь и состояние остаются прежними.
Старый ICS никогда не выдаётся за свежие данные источника.

Изменения по-прежнему требуют двух одинаковых наблюдений; подтверждённые
РФС завершённые кубковые результаты могут применяться сразу. Отказ РФС
не отключает остальное обновление. UID, ссылки на видео и напоминания
за час и за пять минут сохраняются. Перед записью проверяются календарь,
дубликаты и сохранность прежних UID. Каждый файл заменяется атомарно.
Workflow публикует календарь и состояние только после успешного прогона.

В артефакте Actions `updater-diagnostics-…` хранятся журнал и JSON-диагностика
за 14 дней: адрес, HTTP-статус, тип и размер ответа, заголовок страницы,
SHA-256, выбранный источник, причины отказа и отложенные изменения.
Тела страниц, cookies и заголовки авторизации туда не записываются.

Проверка без сети:

```sh
python -m unittest discover -s tests -v
```

Проверка актуальных источников без записи ICS и без увеличения счётчика
подтверждений (диагностический файл при этом создаётся):

```sh
python update_results.py --dry-run --diagnostics diagnostics.json
```

Pull request запускает офлайн-тесты и не зависит от доступности спортивных
сайтов. После слияния в main запускается реальное обновление. Его результат,
а не только зелёный тест PR, подтверждает восстановление публикации.
